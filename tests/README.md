# sumi 回归与视觉基线

应用仍然只有静态 HTML/CSS/JavaScript，无需安装运行时依赖。以下 Python 依赖只用于开发验证。

## 运行

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
node --check app.js
node --check data-store.js
python -m unittest discover -s tests -p 'test_*.py' -v
python tests/visual.py
```

测试自动启动临时本地 HTTP 服务，并使用独立、用完即关闭的浏览器上下文；不修改用户现有浏览器数据。可设置 `SUMI_CHROMIUM=/path/to/chromium` 选择浏览器；否则优先使用系统 Chromium，没有系统 Chromium 时使用 Playwright 下载的版本。

交互测试覆盖新增、编辑、删除、取消/激活、续费付款、重复周期阻止、旧数据读取与额外字段保留、备份往返、取消/拒绝导入、不可信 HTML、异常数据保护、存储拒绝/配额不足、部分保存回滚、中断恢复、过期标签页写入保护、图标选择和上传、表单校验及本地日期。

## 视觉检查

`baselines/` 中的 18 张截图覆盖桌面 1440×1000、iPad 尺寸 820×1180、手机 390×844 的五个页面和新增表单。布局测试另覆盖 320×740、1024×768，并检查长名称日历事件不溢出。截图使用固定时区、时间、示例数据和字体环境，阻止外部图标请求，避免网络导致不稳定。

本次基线生成环境：Debian 13、系统 Chromium 154.0.8037.57、Python 3.12、Playwright 1.62.0、Pillow 12.3.0。操作系统、字体、浏览器版本不同可能产生像素差异。CI 运行交互断言并上传截图供审查；像素比较应在相同渲染环境中执行。当前基线没有暗色模式、真实 Safari 或 iOS/iPadOS 设备覆盖。

`python tests/visual.py` 会重新截图并与基线比较：尺寸变化直接失败；超过 0.1% 的像素存在大于 20/255 的颜色差异时失败。实际截图和差异图保存在被 Git 忽略的 `tests/artifacts/`。只有确认 UI 变化合理后，才显式执行：

```sh
python tests/visual.py --capture tests/baselines
```

与初始提交 `2d34abd` 的截图对比：桌面/iPad 页面保留原有布局；手机搜索筛选改为完整一行，设置按钮缩小间距，窄屏表单增加输入宽度。日期默认值改为本地日历日。在设备上仍需补充触摸键盘、Safari 和系统字体验收。

## 数据保护约定

继续使用 `sumi-data-v1` 和 `sumi-prefs-v1`，正常启动不改写旧数据。旧版订阅/付款字段和未知扩展字段保留；旧版缺失的空集合、可选状态/图标/自动续费字段和偏好值按默认值读取。历史付款的小数精度不被重新舍入，新录入金额最多两位小数。

导入采用完整校验、确认、保存的顺序，拒绝错误结构、重复编号、非法日期/金额/币种/周期及不安全图标 URL。名称和编号作为文本处理。异常本地记录可显示的部分仍可查看，但暂停写入，避免把无法识别的记录覆盖掉。异常提示提供原始数据下载；该恢复文件包含原始字符串，供人工修复，不是可直接导入的正常备份。恢复应先保存原始文件，再导入确认完整的 version 1 备份。

保存前写入 `sumi-write-journal-v1`，同时记录两个旧存储值；部分失败会回滚，浏览器中断留下的记录会在下次启动恢复。写入成功后才更新页面状态。若存储继续拒绝恢复，保留日志并暂停写入，待存储权限/空间恢复后刷新。日志需要额外容量；接近 localStorage 上限时应导出备份并减少大图片。写入前检测其他标签页的已有更改，但 localStorage 不提供跨标签页数据库事务，严格同时写入的冲突解决仍留待后续数据层设计。

仍保留既有业务限制：月末续费锚点、跨多个逾期周期、补录付款与账期关联、删除付款后的日期调整；本轮没有改变这些规则。固定汇率、参考成本图表和站内提醒也保持原有范围。
