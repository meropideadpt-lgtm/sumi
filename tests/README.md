# sumi 回归与视觉基线

应用使用静态 HTML/CSS/JavaScript，无需安装生产依赖。以下 Python 依赖仅用于开发验证。

## 运行

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
node --check app.js
node --check data-store.js
node --check billing.js
node --check icons.js
node --check exchange.js
node --check statistics.js
node --check statistics-view.js
node --check service-catalog.js
node --check logo-upload.js
node --check i18n.js
node --check theme.js
node --check locales/app.js
node --check locales/statistics.js
node --check locales/errors.js
node --test tests/test_*.cjs
python -m unittest discover -s tests -p 'test_*.py' -v
python tests/visual.py
```

测试自动启动临时本地 HTTP 服务，使用独立且用完即关闭的浏览器上下文，不修改用户现有浏览器数据。可设置 `SUMI_CHROMIUM=/path/to/chromium` 选择浏览器；否则优先使用系统 Chromium，没有系统 Chromium 时使用 Playwright 下载的版本。

## 服务目录与图片验证

`service-catalog.js` 提供 72 项可选服务及中英文、常见别名，目录没有金额或价格字段。搜索结果必须按相关性排序，未知名称继续可以自行添加。选择建议会填入品牌名称和 Logo；从 Logo 选择器选择图片则保留非空自定义名称，不覆盖价格、日期、周期和已有分类。

`assets/brands/` 内的 55 个 SVG 与站点一同部署，另外 17 项服务显示统一中性图标。目录测试核对条目数量、类别、名称/别名、搜索排序、资产存在性、安全 SVG 内容及来源记录；缺失图标不可用首字母或随机图形冒充。来源与限制见 [品牌资源记录](../docs/brand-assets.md)。

`logo-upload.js` 对新上传的静态 PNG/JPEG/WebP 检查 MIME、字节签名、结构、12 MiB 原图上限、8192 像素边长及 4000 万总像素限制，并重编码为最长 512 像素、最多 300,000 字节的图片，再要求浏览器解码成功。SVG、动画图、截断内容及类型伪装必须失败。单元测试覆盖解析与错误路径，浏览器测试补充真实图片解码及表单操作。失败的上传不能替换之前的 Logo；关闭选择器或切换选择后，较晚完成的旧上传也不能覆盖新选择。

移除 Logo 后保存空值，刷新、再次编辑、统计和备份往返都不能按名称自动复原。旧版 HTTPS 图标与栅格 data URL 仍可读取；只对已明确记录的旧 CDN 地址进行显示层映射，不批量改写已有订阅。新目录和图片操作不删除付款历史、成本观察或独立汇率缓存。

## 国际化与外观验证

`locales/app.js`、`locales/statistics.js` 和 `locales/errors.js` 集中保存界面及错误文案；`i18n.js` 提供四语言切换、回退与格式化。测试应检查全部资源的语言覆盖及占位参数，不以静态页面存在代替交互验证。设置切换后还需实际完成新增/编辑、续费确认、历史付款、Logo 搜索和上传等流程。

数据保持检查比较切换语言和外观前后的 `sumi-data-v1` 原始字符串及汇率缓存，包括旧版扩展字段、付款小数精度和冻结快照。偏好专用写入只修改 `sumi-prefs-v1`，业务存储原来缺失时仍应缺失；不能因设置切换而填入默认字段、重新排序/序列化数据或新增成本观察。也需验证保存失败、日志恢复与过期页面拒绝写入的行为。

已知类别仅改变显示标签，提交时仍使用原类别值；用户自定义类别、名称、备注及原币金额保持原样。日期控件内部值仍为 ISO 字符串，账期计算不能依赖本地化显示文本。`Intl` 输出以浏览器实现为准，不用强行替换空格或标点来改变持久化金额。

`theme.js` 在样式加载前读取已保存选择，默认浅色。测试应分别覆盖手动浅/深模式、系统模式变化、重新载入、无法读取偏好，以及弹窗打开时的主题变化；系统事件只更新外观，不能让表单草稿丢失。第二轮优化后，内置图标使用透明背景及随主题切换的单色轮廓，自定义图片仍使用原图；表单、图表、日历、错误文本、占位文字、焦点及悬浮状态均需检查。

上述可访问性及浏览器模拟检查不能等同于完整辅助技术审计。原生日期选择器、系统文件选择器、浏览器对话框按钮和真实软键盘需要设备验收；详见 [国际化与外观记录](../docs/i18n-theme.md)。

## 确定性汇率模拟

`browser_support.py` 对 `https://api.frankfurter.dev/v1/**` 的请求提供固定 JSON 响应；测试可以覆盖为断网、HTTP 错误、异常结构或不完整币种报价。模拟数据中的日期和数值是测试输入，不是供应商实时或历史报价。

此路由避免外网变化影响已有回归。测试没有自动向原来的业务存储键注入成本历史或付款汇率；相关用例通过真实表单、备份或明确的 fixture 建立数据。正常网络模式和离线模式都必须保持原币金额，不允许将缺失汇率静默设为 1。

成功付款的展示金额只读取自身冻结矩阵，测试会先确认付款，再改变当前报价和展示币种，检查原始付款及冻结结果未被新汇率改写。旧付款没有快照时，仅原币金额可以精确显示，不用当前参考汇率倒算历史。

## 数据保护与统计口径

继续使用 `sumi-data-v1`、`sumi-prefs-v1` 和 version 1 备份。普通启动不改写旧业务数据；已有字段、扩展数据和历史付款的小数精度保留，新录入金额最多两位小数。

新可选字段包括订阅的 `category`，付款的 `fxSnapshot`，以及业务数据中的 `costHistory`。前一阶段的 `billingAnchor`、付款 `status`、`advancesSchedule` 和 `scheduleArchived` 保持兼容。旧付款没有 status 时仍语义为成功，没有 cycleDate 时不猜测账期，没有 fxSnapshot 时不伪造确认汇率。

`costHistory` 保存观察到的原币金额、周期、类别、状态与生效日期。启动时只可在内存中展示今天的观察，不补写旧存储。用户记录基线或正常修改业务数据后，后续观察随同一次成功保存追加。旧记录首次基线以前的状态保持未知，新增订阅才可以确认其创建以前不存在；取消和删除后也保留已有观察。同一天以最后观察状态计算，不宣称逐分钟计费精度。

月度趋势表示已观察日期的平均月成本；年度趋势与期间占比累计已记录日期的摊销成本。它们按当前参考汇率换算，并明确提示部分范围和缺失报价。实际付款则按成功记录的付款日期筛选，使用每笔确认时的冻结汇率，不能混入当前成本或失败次数。没有可用数据时显示空状态，不能补出虚假历史曲线；部分金额无法换算时保留实际次数和原币汇总并提示。

导入先完整校验，再确认和保存；拒绝非法结构、重复成功账期、无效日期/金额/周期、币种格式及不安全图标 URL，并核对冻结快照是否匹配原币金额和换算结果。币种代码格式合法不表示接口支持换算。名称、类别和编号作为文本处理。

异常记录可显示的部分仍可查看，但暂停写入，避免覆盖无法识别的内容。提示提供原始数据下载；该文件包含原始字符串，供人工修复，不是可直接导入的普通备份。恢复前先保存原始文件，再导入确认完整的备份。

偏好设置专用写入保留 `sumi-data-v1` 的原始字节，不重新校验或序列化业务记录；语言、主题及其他显示偏好的更改不追加成本历史。业务编辑仍使用原有完整校验与保存路径。

保存前写入 `sumi-write-journal-v1` 记录两个旧业务值；部分失败会回滚，浏览器中断留下的记录在下次启动恢复。持久化成功后才更新页面状态。存储继续拒绝恢复时保留日志并暂停写入，待权限或空间恢复后刷新。恢复日志和每笔冻结矩阵需要额外容量，接近 localStorage 上限时应先导出备份。

汇率缓存使用独立的 `sumi-fx-cache-v1`，只保存最近一次有效获取。缓存失败不会改写业务数据；业务备份包含付款冻结快照和成本历史，无需依靠以后仍可下载到相同汇率。
