# sumi

一个纯白与淡蓝风格的个人订阅管理网站初版。无需安装依赖，可直接部署到 GitHub Pages。

## 部署到 GitHub Pages

1. 在 GitHub 新建仓库 `sumi`。
2. 将本目录的 **index.html、styles.css、data-store.js、billing.js、icons.js、app.js、README.md** 上传到仓库根目录（不要只上传 zip）。
3. 进入仓库 **Settings → Pages → Build and deployment**，Source 选 **Deploy from a branch**，Branch 选 `main`，文件夹选 `/(root)`，保存。
4. 等待 Pages 部署完成，打开 GitHub 显示的网站地址。

## 当前实现

- 响应式首页、订阅列表、统计、日历、设置；手机首页紧凑摘要与底部导航，重要提醒完整保留
- 添加、编辑、删除订阅；品牌图标搜索与自定义上传
- 订阅详情、取消与恢复；成功/失败付款记录、补录、编辑和删除付款
- 站内续费提醒、JSON 备份/导入、浏览器 localStorage 持久化
- 平均月成本计算与简单币种切换

## 重要限制

- **币种换算是演示用固定汇率，不是实时汇率**；不能用于准确财务核算。
- **历史月度趋势尚未实现**；首页图表仅重复展示当前成本参考值，并明确标注。
- **国际化尚未实现**；当前仅简体中文可用。
- 品牌 Logo 依赖 Simple Icons CDN，部分品牌可能缺失；图标使用须在发布前审查品牌使用条款。
- 数据只保存在当前浏览器的 localStorage，换设备不会同步。清理网站数据可能丢失记录，请导出 JSON 备份。
- 已支持月底/闰年账期、逐期结清逾期付款、失败记录、去重及付款历史编辑；价格变更历史和真实支付平台对接尚未实现。
- 日历只展示当前保存的下一次续费日期，不自动生成所有未来周期。
- 已加入核心交互自动化测试与桌面/iPad/手机尺寸截图基线；真实设备及 Safari 验收仍待补充。

## 本地开发与测试

运行 `python3 -m http.server 8000` 即可启动静态网站。应用没有构建步骤或生产依赖。

测试环境安装、回归命令、视觉基线及异常数据恢复方式见 [tests/README.md](tests/README.md)。保留原有 `sumi-data-v1` / `sumi-prefs-v1` 存储格式；遇到异常数据时请先导出原始数据，再用确认完整的备份恢复。

## 账期与付款规则

每个订阅保留原始扣款日：例如 1 月 31 日月付，经 2 月 28 日后会回到 3 月 31 日；按季、半年和年付同样处理短月、跨年与闰年。逾期付款按账期逐期确认，不自动跳过尚未结清的月份。只有用户明确确认成功并且本地保存成功后，才加入成功历史并推进至下一未付款账期。失败记录可查看和编辑，不计入实际付款，也不推进续费日。本应用只记录结果，不会实际发起扣费。

补录付款可以明确关联账期，也可以保留为空、仅记历史；旧版未关联的补录不会被猜测归属。相同订阅和账期不能重复记录成功付款。删除或改为失败的关联成功付款会重新打开该账期；修改金额或实际付款日期不会重算账期。

显式修改下次续费日或周期，会以新日期建立扣款日基准，并将旧关联付款保留为旧账期历史，防止以后编辑或删除旧记录影响新计划。取消/恢复订阅保留原账期和历史，不会自动跳到今天。旧数据未保存原始扣款日时，优先使用可匹配的历史账期，否则沿用当前保存的日期；无法从缺失的信息还原已经漂移的日期，可在编辑订阅时纠正下次续费日。
