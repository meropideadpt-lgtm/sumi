# 国际化与外观记录

第五阶段基于 PR #4 的 `7a1e2ba611683fa884bccfdfcd592f8b2399a402`，保留静态 HTML、CSS、JavaScript 架构、72 项服务目录及现有账务逻辑。开发分支为 `feat/i18n-theme-stage5`，Draft PR #5 目标为 `feat/service-catalog-stage4`。本阶段不部署正式版本，不合并已有 PR，也不修改 main。

## 用户交互

设置中可选择简体中文（`zh-CN`，默认）、繁體中文（`zh-TW`）、日本語（`ja-JP`）或 English（`en`）。选择后立即重绘应用并更新页面 `lang`，无需刷新；成功保存后重新打开应用仍使用原选择。语言名称使用各自的原文，方便在不熟悉当前界面语言时找到所需选项。

外观选项为浅色、深色和跟随系统。默认浅色保持原有设计；跟随系统监听 `prefers-color-scheme: dark` 的变化，手动浅色或深色不被系统事件覆盖。系统外观变化直接更新主题，不重新建立页面与表单，因此不会主动丢弃草稿、焦点或中文输入法状态。

## 翻译资源与回退

资源按界面职责集中管理：

| 文件 | 用途 |
| --- | --- |
| `locales/app.js` | 导航、页面、设置、订阅/付款弹窗、Logo 管理、提示与确认 |
| `locales/statistics.js` | 独立统计页的筛选、图表、摘要、警告与付款汇总 |
| `locales/errors.js` | 数据校验、存储、账期、汇率及图片错误的显示映射 |
| `i18n.js` | 语言状态、占位参数、回退、错误映射、已知类别显示和 `Intl` 格式化 |

翻译使用语义键和文本占位参数，参数在生成 HTML 时仍必须转义。不会通过遍历页面文字来替换用户内容。核心模块既有的校验规则和错误条件保持不变，错误在界面边界按所选语言显示；无法识别的错误使用稳定的通用提示。

当前语言缺少某项文案时，先回退到该项简体中文；该项也不存在时使用明确提供的显示回退或本地化通用提示。缺少参数不会输出 `undefined`，缺少资源不会直接显示内部翻译键。新增文案应同时补齐四语言和参数，并通过资源覆盖检查；回退用于保护异常路径，不能代替正常翻译。

## 显示与数据的边界

日期、数字、百分比和货币使用 `Intl` 显示，英文数量文案使用 `Intl.PluralRules` 选择单复数，统计图表的年月标签也随语言改变。日历日期按明确的日历日期格式化，避免时区把保存日期显示为前一天；时间戳可以按用户本地时区显示。原生 date/month 输入仍提交 ISO 日期或年月值，业务逻辑不解析界面展示文本；本阶段没有重做浏览器原生日期选择器。

语言切换不修改以下数据：

- 用户填写的订阅名称、备注、自定义类别及其他扩展字段。
- 价格、原始币种、账期日期、订阅/付款状态和其他持久化枚举。
- 付款历史、确认时的冻结汇率与换算结果、成本观察及汇率缓存。
- 预置服务的品牌名称、目录 ID、中英文和常见别名。

已知类别可在界面显示译名，但保存与统计分组继续使用原类别值。例如 `云存储` 可以显示为 `Cloud storage`，不会为了语言切换而把已有记录改成英文。未知的自定义类别保持用户输入，不自动翻译。

设置使用偏好专用保存路径。它保留旧 `sumi-data-v1` 原始字符串，包括空白、字段顺序、扩展字段和旧记录小数；原本没有业务存储时也不创建空业务记录。只有 `sumi-prefs-v1` 保存所选语言、主题等偏好，仍使用既有写入日志、失败回滚和过期页面保护。更新显示偏好不触发成本历史记录，原有业务编辑/导入路径继续完整校验。保存失败时保留先前生效的设置并显示错误，不把未保存的选择当作持久化成功。

## 主题加载与视觉规则

`theme.js` 作为 head 中的同步脚本，在样式和应用渲染之前读取已保存外观，为根元素设置主题、背景和 `color-scheme`，以减少冷启动时先浅后深的闪烁。偏好不可读取或格式异常时仍可安全使用浅色，随后由原有数据恢复提示处理。预加载逻辑不写用户数据；页面就绪后继续同步兼容的 `body.dark` 类。

深色使用深灰背景、细边框、清晰文字和适度蓝色强调，覆盖首页、列表、统计、日历、设置、抽屉、弹窗、Logo 选择器和表单。品牌图片保留原色，以浅色底板保证黑色或透明品牌图形可辨认，不统一反色或替换品牌内容。按钮、输入、错误提示、焦点和悬浮状态一并适配。浅色仅改善必要文字和焦点提示的对比度，保留原有背景、布局和图表配色；现有减少动态效果设置继续适用。

## 验证范围与设备验收

最终自动化数量和结果统一记录在 [测试说明](../tests/README.md)，不以父阶段 CI 成功代替第五阶段验证。四语言检查包括主要页面、弹窗、确认与错误路径，以及实际新增/编辑、付款和 Logo 流程；数据保持检查需要比较原始存储，而不仅比较页面文字。

桌面、手机及 iPad 尺寸、触控和系统外观事件由 Linux Chromium 自动化模拟。它们不代表真实 iPad Safari、iPhone、系统字体、原生控件或辅助技术已通过验收。仍需在实际设备上确认：

1. 四语言切换、长文案、日期与数字显示、系统软键盘及中文/日文输入法。
2. 手动浅色/深色、跟随系统、冷启动主题，以及已打开表单时系统切换不会丢失草稿。
3. 统计图表、日历、Logo 选择器和上传体验，以及键盘焦点、屏幕阅读器标签和错误提示。
4. 实际 sumi 页面中的 Frankfurter fetch、CORS、缓存和手动刷新。用户已报告 iPad Safari 地址栏能够访问接口，但这不等于页面内请求已经验证；云环境直接请求限制继续见 [汇率接入记录](frankfurter-v1.md)。

原生日期选择器、系统文件选择器以及浏览器确认对话框的系统按钮文字受浏览器/操作系统语言控制；应用自己的标签、对话内容和校验提示随所选语言切换。不同 `Intl` 实现可能产生标点、货币空格及字体差异，不应通过改写原始数据消除这些显示差异。
