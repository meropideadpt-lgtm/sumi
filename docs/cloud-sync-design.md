# 云同步准备：保留标识、隔离身份、显式迁移

这是后续阶段的设计约束。本阶段只实现 Supabase Auth 和本机工作区隔离，没有数据库迁移脚本、私有表、bucket、云端业务请求或自动同步。

## 现有数据如何保留

现有 `sumi-data-v1`、备份版本 1 和记录 ID 不变。订阅、付款、成本观察的已有标识原样保留，不要求旧 ID 是 UUID，不因登录生成替代 ID。已确认付款的原币金额、日期和完整冻结汇率快照作为不可重新定价的业务事实；未来修改付款历史应保留修订记录。图片原有 `sumi-logo:<sha256>` 内容引用与内嵌图片仍可读。

工作区标识版本 1 由 `(projectOrigin, authUserUUID)` 唯一确定。登录只是选定本机分区，不能自动复制访客记录、把本地空数组上传为全量删除，或用服务器空结果覆盖本机数据。

## 未来首次迁移流程

1. 用户显式启用同步，验证当前 JWT 对应账号，导出完整含图片的本地备份。
2. 在只读预检中统计订阅、付款、成本观察、设置和图片的数量、原 ID、内容摘要；验证重复 ID、缺失图片和金额精度。展示与现有云端记录的差异及冲突，不直接覆盖任一侧。
3. 使用有版本的迁移清单与独立迁移 operation ID 分批暂存上传；保留原 ID 和图片内容哈希。记录上传进度，失败可幂等重试。
4. 服务端事务验证用户所有权、父子关系、版本及清单完整性后提交业务记录与迁移完成标记。图片先暂存，只有全部必需图片可用才完成清单。
5. 客户端读回核验数量和摘要后提交本地同步游标。旧访客副本、原图片与备份始终保留，不自动删除。中断可以安全续传，不能把半完成迁移视为成功。

业务记录建议使用复合主键 `(owner_id, record_id)`；付款关联以 `(owner_id, subscription_id)` 外键防止跨账号引用。未来同步元数据单独加有版本的存储，不把旧 localStorage 数据原地批量重写；若最终迁移业务到 IndexedDB，须先验证完整副本并有回滚标记，再切换读写。

## 版本、离线与删除

每条云端记录包含服务器递增 `revision`、服务器 `updated_at`、`deleted_at`；记录类型和 schema_version 明确。客户端时间不能决定覆盖胜负。每个离线操作含唯一 `operation_id`、`device_id`、`record_id`、`base_revision` 与操作类型，并和本地业务变更以同一事务写入 outbox。服务端按 operation ID 去重，用 revision 做 compare-and-swap。

离线删除写墓碑而非立即物理删除。未确认删除保留在 outbox；客户端按同步游标接收墓碑，避免断网旧设备把删除的数据重新创建。服务端墓碑只有在游标保留期和设备确认规则满足后才清理；超过保留期的设备必须完整重新对账，不能直接上传旧快照。启用同步以前已经删除且没有记录的内容无法重建，不能凭本地缺失推断云端删除。

相同 base_revision 的并发修改若冲突，保留本机草稿与服务器版本并要求选择/合并，不对金额、付款、账期或冻结汇率使用无提示的“最后写入胜出”。订阅删除与新增付款冲突需要显式处理；付款成功确认必须有可幂等检查的业务标识，不能因网络重试重复记账。

设置可按字段同步，区分账号偏好与设备偏好；语言/主题是否跨设备同步需在下一阶段明确。访问令牌、刷新令牌、密码、临时 UI 状态、恢复日志、工作区选择不作为业务数据上传。参考汇率缓存可各设备重取；历史付款冻结快照必须随记录原样保留。

## 图片迁移

图片使用私有 Storage bucket，路径为 `<verified-auth-uid>/<sha256>.<validated-extension>`。服务端验证 MIME、实际文件类型、尺寸、大小与内容摘要，禁止任意 SVG/HTML。保持内容哈希引用，使用短期签名 URL 或经过鉴权的下载，不能把长期公开 URL 作为安全边界。

上传和数据引用不构成单一跨服务事务：先暂存图片、校验，再提交引用；迁移中断时保留可续传清单。只有确认没有活动引用或待提交操作后才清理孤儿图片。下载成功并校验后写入当前账号 IndexedDB，旧访客图片不移动、不删除。

## RLS 是启用云端业务读写的前置条件

本阶段没有创建任何私人表或 bucket，未执行远端 RLS 测试，不能据此声称现有项目安全。下一阶段上线私有数据前必须做到：

- 所有私有表启用 RLS；只授予必要的 authenticated 权限，anon 不得读写。
- SELECT/UPDATE/DELETE 的 USING 与 INSERT/UPDATE 的 WITH CHECK 同时约束 `(select auth.uid()) = owner_id`。不能只检查读取而允许更改 owner_id；所有相关子表和外键也必须包含 owner。
- RPC 从验证后的 JWT 获取所有者，不能信任请求的 owner_id；避免可绕过 RLS 的 SECURITY DEFINER，必要时审计 search_path、授权和函数体。
- Storage bucket 必须 private；对象权限同时检查 bucket 和路径首段为 auth.uid()，更新/删除同样约束；签名链接遵守最短必要有效期。
- 前端仅保留 URL/Publishable Key。任何管理迁移脚本只在受控服务端运行，管理员密钥绝不进入网页、仓库、客户端日志或测试快照。

用临时用户 A、B 和匿名客户端执行真实集成验收：A 自己 CRUD 成功；A 对 B 的列表、指定 ID 查询、插入、更新、删除、owner 变更、外键引用、RPC、Storage 上传/下载/覆盖/签名全部拒绝；匿名全部拒绝；过期/撤销会话拒绝。另测版本冲突、重复 operation、断点恢复、墓碑传播、不同设备的离线修改和金额冻结。测试清理仅限专用测试记录，不能触碰用户已有数据。
