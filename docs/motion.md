# 第六阶段交互与视口

`motion.js` 只读取动效偏好和浏览器视口，不写入订阅、付款或汇率数据。设置提供「跟随系统」与「减少动态效果」；系统开启减少动态效果时始终减少，即使应用使用跟随系统。旧数据没有 `motion` 时默认跟随系统。

统一过渡使用 140 / 220 / 280 毫秒，以及没有回弹的 `cubic-bezier(.2,.7,.2,1)`。页面、列表和图表仅在切换页面时轻量进入，弹窗与抽屉只在打开或目标改变时进入，主题前景与背景成对切换，并以轻量整体淡入衔接；不插值前景和背景，以免过渡中间产生低对比度。搜索和汇率更新不会重新播放整个页面的动画；进入动画完成后清除作用类，后续局部列表更新也不会被动画规则影响。

显式关闭弹窗使用现有节点的 Web Animations API 淡出，140 毫秒后执行关闭回调。没有复制表单或保存临时业务数据。重复点击受到拦截，取消、动画 API 异常或超时都会完成关闭；减少动态效果时立即关闭。应用集成需要检查回调中的目标身份，防止较晚完成的旧关闭操作影响新弹窗。保存成功后的业务状态仍立即提交，不等待动画。

`visualViewport` 的 resize / scroll 事件按动画帧合并，更新 `--viewport-height` 与 `--viewport-offset`。弹窗和抽屉按可见高度滚动，输入控件在对话框内可滚动至键盘上方。只有输入控件聚焦、视口缩短超过 120 像素且未放大时才判断键盘打开；缩放不冒充键盘。触控手机和平板使用至少 16px 的表单字号，减少 iOS 聚焦自动缩放；安全区内边距保留，手机首页图表继续隐藏。

自动化包含 Node 偏好、系统事件、动画状态和视口事件测试，以及 Chromium 手机、平板和桌面模拟视口测试。这些测试不能替代真实 Safari / iPadOS 的软键盘、缩放、分屏、横竖屏和系统减少动态效果验收。
